# تقييم مزودي الذكاء الاصطناعي (تفريغ الصوت + الاستخراج السريري)

> **الحالة (2026-10-19): لم يُربط أي مزود حقيقي.** المنصة تعمل بمزود تجريبي محلي. ربط مزود حقيقي يحتاج قرارك وموافقة قانونية، ولن يُرسل أي صوت أو نص لمريض حقيقي قبل ذلك.

## 1. القيد الأهم: الأهلية من داخل سوريا
- **OpenAI:** لا تنشر قائمة بالدول غير المدعومة؛ أي دولة غير موجودة في قائمة الدول المدعومة غير مدعومة. المصادر الثانوية وتقارير المستخدمين في 2026 تشير إلى أن **سوريا ليست مدعومة** للـAPI. يجب التأكد مباشرة من صفحة OpenAI الرسمية قبل أي خطوة. ([OpenAI — Supported countries](https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories))
- **العقوبات الأمريكية:** أُلغي برنامج عقوبات سوريا لدى OFAC عام 2025 (الرخصة العامة 25 ثم الأمر التنفيذي 14312)، **لكن قيود التصدير (EAR) على البرمجيات والتقنية ما زالت قائمة جزئياً**، والخدمات السحابية تحتاج تقييماً حذراً من المزود نفسه. ([Goodwin](https://www.goodwinlaw.com/en/insights/publications/2025/10/alerts-otherindustries-syria-sanctions-subside)، [Baker McKenzie](https://sanctionsnews.bakermckenzie.com/ofac-and-bis-issue-final-rules-removing-syria-sanctions-regulations-and-relaxing-export-controls-for-syria/)، [وزارة الخارجية الأمريكية — ديسمبر 2025](https://www.state.gov/wp-content/uploads/2025/12/updated-Advisory-for-Syria-Final.pdf))
- **ممنوع:** استخدام VPN أو حسابات بأسماء/دول أخرى للالتفاف على هذه القيود (شرطك الصريح، وهو أيضاً مخالف لشروط المزودين).

**النتيجة:** الخيار التقني الأفضل يجب أن يمر أولاً بسؤال قانوني: من الكيان المتعاقد (شركة داخل سوريا أم خارجها؟) وأين تُعالج البيانات؟ هذا قرارك.

## 2. معايير الاختيار
| المعيار | لماذا |
|---|---|
| الأهلية القانونية للتعاقد والاستخدام من/لسوريا | شرط مسبق |
| اتفاقية معالجة بيانات (DPA)، عدم استخدام البيانات للتدريب، مدة احتفاظ صفرية أو قصيرة | بيانات صحية حساسة |
| موقع المعالجة | متطلبات قانونية محلية محتملة |
| دقة التفريغ للعربية **باللهجة السورية** وللأدوية بالإنجليزية | جوهر الميزة |
| تمييز المتحدثين (Diarization) والطوابع الزمنية | لربط المعلومة بقائلها |
| مخرجات منظمة (JSON Schema) للاستخراج | لتقليل الأخطاء |
| التكلفة لكل دقيقة صوت + لكل استخراج | تسعير الطبيب والهامش |
| الاستقرار والدعم | منتج تجاري |

## 3. فئات الخيارات (للدراسة بعد الحسم القانوني)
| الفئة | مزايا | مخاطر |
|---|---|---|
| مزودو النماذج الكبرى عبر API (تفريغ + نموذج لغوي) | جودة عالية للعربية الفصحى، مخرجات منظمة | الأهلية لسوريا غير مؤكدة، نقل بيانات للخارج |
| منصات سحابية كبرى (خدمات Speech + LLM مُدارة) | عقود مؤسسية وDPA | قيود جغرافية/تصدير مشابهة |
| مزودون إقليميون متخصصون بالعربية | قد يدعمون اللهجات الشامية بشكل أفضل، وقد تكون الأهلية أسهل | نضج متفاوت، يحتاج تقييماً فعلياً |
| تشغيل نموذج مفتوح (مثل Whisper) على خادمك | لا نقل للبيانات | **تعارض مع رغبتك بتقليل الصيانة** ويحتاج GPU؛ يبقى بديلاً احتياطياً |

## 4. خطة التقييم الفعلي (جاهزة للتنفيذ بعد الموافقة)
1. مجموعة اختبار **اصطناعية أو مرخصة**: 30–50 حواراً بلهجة سورية (رقاوية/شامية) يؤديها ممثلون بموافقة، تغطي: أدوية تجارية محلية، جرعات بالأرقام المنطوقة، خلط عربي/إنجليزي، اختصارات (HbA1c، CBC)، ضوضاء عيادة.
2. المقاييس: WER للتفريغ؛ **معدل خطأ أسماء الأدوية**؛ **معدل خطأ الجرعات** (الأخطر)؛ دقة/استدعاء الحقول المستخرجة؛ معدل «الاختراع» (أي معلومة غير موجودة في الصوت) ويجب أن يكون صفراً للتشخيص والجرعات.
3. معيار القبول المقترح: صفر جرعات مخترعة، ≥95% صحة الجرعات المذكورة، ≥90% أسماء الأدوية، مع وضع علامة مراجعة على كل ما دون ذلك.
4. يُنفذ التقييم عبر نفس الواجهة `SpeechToTextProvider/ClinicalExtractionProvider`؛ إضافة مزود = فئة واحدة جديدة دون تغيير الواجهات.

## 5. الوضع الحالي في الكود
- `MockSpeechToText` + `RuleBasedClinicalExtractor` (محلي، بلا تكلفة خارجية؛ التكلفة المسجلة **تقديرية** لاختبار المحاسبة).
- `ManagedCloudProviderPlaceholder`: مكان المحوّل الحقيقي، غير مفعّل.
- قفل أمان: أي مزود `is_real` يُرفض ما لم يُضبط `HAYAT_AI_REAL_PROVIDERS_APPROVED=true`.

## 6. ما أحتاجه منك
1. الكيان القانوني المتعاقد ومكان معالجة البيانات المقبول.
2. موافقة على تقييم مزود محدد (مع تكلفة تقديرية) باستخدام بيانات اصطناعية فقط.
3. بعد نجاح التقييم: موافقة قانونية على الاستخدام مع مرضى حقيقيين + نص موافقة المريض.
