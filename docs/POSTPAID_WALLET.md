# المحفظة الآجلة للأطباء (Postpaid Wallet)

> المصدر: `requirements/PHASE2_REQUIREMENTS.md` §19–§32. الكود: `backend/apps/billing/`. الاختبارات: `backend/tests/test_wallet.py` (19 اختباراً) + `apps/web/e2e/ai-wallet-acceptance.spec.ts`.

## القاعدة الذهبية
**لا يوجد في الكود أي مسار يوقف HayatTek AI بسبب الدين.** البوابة الوحيدة لبدء جلسة هي `billing.services.ai_enabled(practitioner)`، وهي تقرأ مفتاحاً يدوياً (`AIScribeAccess.enabled`) يغيره Super Admin فقط، ولا تقرأ الرصيد إطلاقاً. الاختباران `test_usage_continues_with_large_debt_no_auto_disable` و`test_postpaid_debt_never_blocks_but_manual_switch_does` يثبتان ذلك عند دين يتجاوز 1,000 دولار.

## إشارة الرصيد
| الرصيد | المعنى |
|---|---|
| موجب | رصيد دائن لصالح الطبيب |
| صفر | لا دين ولا رصيد |
| سالب | الطبيب مدين للمنصة؛ المبلغ المستحق = القيمة المطلقة |

`الرصيد = مجموع كل القيود` (الدفعات والأرصدة الدائنة موجبة، الرسوم والخصومات سالبة).

## النماذج
| النموذج | الدور |
|---|---|
| `WalletAccount` | محفظة لكل (طبيب أو منشأة) وعملة. `balance` نسخة مخزنة تُحدَّث داخل نفس المعاملة مع القيد، وتُطابق دائماً `recompute_balance()`. |
| `LedgerTransaction` | قيد مالي **غير قابل للتعديل أو الحذف** (Trigger في PostgreSQL + حماية في Django). مبلغ بإشارة، `balance_after`، النوع، المنشأة، المرجع، رقم الإيصال، `reverses`، `idempotency_key` فريد. |
| `PricingPlan` / `PriceAssignment` | خطط تسعير (سعر الدقيقة، نمط التقريب، حد أدنى)، وإسناد خطة لطبيب من تاريخ سريان. |
| `AIUsageRecord` | قياس جلسة AI واحدة: **فريد لكل جلسة**. يحفظ لقطة السعر المطبق والمبلغ المفوتر وتكلفة المزود (فعلية أو تقديرية) والهامش. |
| `AIScribeAccess` / `AIAccessEvent` | المفتاح اليدوي وسجله (من، متى، لماذا). |
| `OrganizationPayerRule` | مستقبلاً: منشأة تدفع عن أطبائها. غير مفعّل افتراضياً. عند تفعيله تُفوتر الجلسة **لمحفظة واحدة فقط** (المنشأة) — لا فوترة مزدوجة. |
| `BillingSettings` | حدود التنبيهات (معلوماتية فقط). |

**قرار تصميم:** دفتر قيود أحادي لكل محفظة (Single-entry, signed) بدلاً من قيد مزدوج كامل؛ يحقق قابلية إعادة الحساب والتدقيق المطلوبة بأبسط بنية، ويمكن تصديره لاحقاً لنظام محاسبي مزدوج. (ADR-025)

## الحسابات المالية
- `Decimal` فقط؛ `money()` ترفض `float` وتقرّب للسنت (ROUND_HALF_UP).
- التسعير: `billable_seconds` حسب نمط التقريب (لأعلى دقيقة / نصف دقيقة / بالثانية) ثم `المبلغ = الثواني/60 × سعر الدقيقة`. مثال: 10 دقائق × 0.10 = 1.00 دولار؛ 61 ثانية بتقريب الدقيقة = 0.20.
- تغيير السعر لا يمس القيود القديمة (كل استخدام يحفظ السعر المطبق).

## متى تُحتسب الرسوم
- عند انتقال الجلسة إلى `ready` (المسودة متاحة للمراجعة)، **مرة واحدة**: قيد `AIUsageRecord` فريد + `idempotency_key = ai:<session_id>` في دفتر القيود + قفل صف المحفظة.
- لا تتكرر الفوترة عند: تحديث الصفحة، إعادة إرسال الطلب، تكرار Callback، إعادة تشغيل مهمة Celery، أو انقطاع ثم استئناف (اختبارات `test_repeated_charge…`، `test_full_session_bills_once…`، والتزامن الحقيقي).
- الفشل: لا رسوم على الطبيب، وتُسجل تكلفة المزود في `AIUsageRecord(status=not_billable)`. إعادة المحاولة الناجحة تُفوتر مرة واحدة وتجمع التكاليف.
- إعادة المعالجة الاختيارية المدفوعة: غير متاحة حالياً (إعادة المحاولة بعد الفشل مجانية).

## العمليات اليدوية (Super Admin فقط)
| العملية | الأثر |
|---|---|
| تسجيل دفعة | قيد موجب + إيصال `RC-YYMM-XXXXXX` + هوية المستلم. مفتاح idempotency من الواجهة يمنع التكرار عند إعادة الضغط. |
| عكس عملية | قيد معاكس بسبب مكتوب، الأصل يبقى. لا يُعكس القيد مرتين، ولا تُعكس العملية العكسية. |
| رصيد مجاني / خصم يدوي / تصحيح رسوم / استرداد / تسوية | قيود موقّعة حسب النوع بسبب إلزامي. |
| تعديل السعر | خطة خاصة أو خطة موجودة، تسري على الجلسات الجديدة. |
| تفعيل/إيقاف AI | مع سجل. الجلسات قيد المعالجة تكتمل وتُفوتر مرة واحدة؛ يُمنع بدء جلسات جديدة فقط. |

الطبيب لا يستطيع تسجيل دفعة أو تغيير سعر أو قراءة محفظة غيره؛ مدير المنشأة لا يصل للمحافظ إطلاقاً (لا توجد صلاحية تفويض بعد).

## الواجهات
- **Super Admin:** `/app/admin/wallets` (مؤشرات، تنبيهات، جدول قابل للبحث والتصفية والترتيب، خطط التسعير، حدود التنبيهات، تصدير CSV وطباعة PDF) و`/app/admin/wallets/<id>` (بطاقات، كشف حساب، دفعة، تسوية، عكس، سعر، تفعيل/إيقاف، سجل التفعيل).
- **الطبيب:** `/app/wallet` «حسابي المالي» دون تكلفتنا أو هامشنا.
- **الطباعة:** `/print/receipt/<id>` (إيصال) و`/print/billing/debts` (كشف المديونية → PDF من المتصفح، ADR-009).
- كشوف الحساب **لا تحتوي** أسماء مرضى أو تشخيصات أو نصوص حوار.

## API
`/api/v1/billing/admin/{overview, alerts, settings, export.csv, plans, practitioners/{id}[/transactions|payments|adjustments|price|ai-access|ai-access-events], transactions/{id}[/reverse|receipt]}` و`/api/v1/billing/me[/transactions[/{id}/receipt]]`.

## خارج النطاق حالياً
الدفع الإلكتروني، تعدد العملات الفعلي (البنية جاهزة: حقل العملة + قيد العملة في الدفعة)، تفويض مدير المنشأة، الفوترة الشهرية بالفواتير الضريبية.
