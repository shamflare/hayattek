## 2. المراجعة الأمنية (§39)
| البند | النتيجة |
|---|---|
| المصادقة | Argon2، قفل بعد 5 محاولات، حد معدل للدخول، توكنات موبايل مُجزأة (hash) قابلة للإبطال، MFA (TOTP) مُلزم في إعدادات الإنتاج. |
| التفويض و IDOR/BOLA | محرك صلاحيات مركزي، 404 للسجلات غير المسموحة مع تدقيق؛ اختبارات تغيير المعرفات لكل وحدة (السجلات، المستندات، DICOM، جلسات AI، إيصالات المحفظة). |
| العزل بين المنشآت | سجلات الشبكة بموافقة محددة النطاق والمدة؛ مختبر. |
| الوصول للملفات | تخزين خاص، تنزيل عبر الـAPI بعد الصلاحية والتدقيق، فحص فيروسات وحجر صحي، لا روابط عامة، Orthanc خلف Django. |
| الصلاحيات المالية | Super Admin فقط للدفعات والتسويات والأسعار والتفعيل؛ الطبيب يقرأ محفظته فقط؛ مدير المنشأة بلا وصول؛ دفتر قيود غير قابل للتعديل على مستوى قاعدة البيانات. |
| حالات السباق | قفل صفوف + قيود فريدة + اختبار تزامن حقيقي (دفعات وفوترة متزامنة). |
| إدارة الأسرار | `.env` خارج git؛ الإنتاج يرفض الإقلاع دون الأسرار، ويرفض الماسح الوهمي ومزود الرسائل Console؛ مفتاح تشفير الصوت إلزامي. |
| أمن الجلسات | كوكي HttpOnly/SameSite، Secure + HSTS في الإنتاج، CSRF، إبطال الجلسات عند تغيير كلمة المرور. |
| تخزين الصوت | مشفّر (Fernet)، احتفاظ محدد وحذف، وصول المؤلف فقط. |
| سجلات التدقيق | محمية بـTrigger؛ تشمل الوصول للسجلات والمستندات وDICOM وأحداث AI والمحفظة. |
| خصوصية البيانات | لا PHI في الـLogs؛ كشوف الحساب بلا أسماء مرضى أو تشخيصات؛ مدير المنصة بلا وصول طبي (مختبر). |
| الاستقبال | لا يقرأ البيانات الطبية (مختبر)؛ يرى الهوية فقط. |

**مخاطر متبقية معروفة:**
1. MFA: مفروض الآن على مستوى الـAPI عند `HAYAT_ENFORCE_MFA=true` (افتراضي الإنتاج): حسابات الطاقم والإدارة دون MFA تُمنع من كل endpoint عدا الإعداد (`test_mfa_enforcement_blocks_staff_until_enrolled`). لم يُطبق بعد: رموز استرداد احتياطية عند فقدان الهاتف (يُعاد الضبط حالياً من إدارة المنصة).
2. OCR يقرأ الأرقام العربية الهندية بضعف (تُترك فارغة للمراجع).
3. عارض DICOM غير مخصص للتشخيص؛ لا إزالة للنصوص المحروقة في البكسلات.
4. لم يُجرَ اختبار اختراق خارجي مستقل.
5. تطبيق الموبايل لم يُختبر على جهاز حقيقي (انظر `MOBILE_TEST_PLAN.md`).

## 3. الحسابات التجريبية والأسرار (§40)
- الحسابات التجريبية كلها تحت النطاق المحجوز `@hayattek.test` وكلمة مرورها الثابتة **للتطوير فقط**؛ `seed_demo` يرفض العمل إن كان `DEBUG=False`.
- **إجراء إلزامي قبل أي إطلاق:**
  1. `manage.py disable_demo_accounts --dry-run` ثم بدون `--dry-run` (يعطّل الحسابات ويبطل الجلسات والتوكنات دون حذف تاريخ التدقيق).
  2. توليد أسرار جديدة: `DJANGO_SECRET_KEY`، `HAYAT_AI_AUDIO_KEY` (Fernet)، كلمات مرور PostgreSQL وRedis وOrthanc وS3، عبارة مرور النسخ الاحتياطي — وتخزينها في مدير أسرار (لا في git).
  3. قاعدة بيانات إنتاج **جديدة** (لا تُنسخ قاعدة التطوير).
  4. إنشاء حساب Super Admin حقيقي مع MFA.

## 4. النشر (§41) — جاهز كقوالب، لم يُنشر
| العنصر | الملف |
|---|---|
| إعدادات إنتاج منفصلة | `backend/config/settings/prod.py` |
| Docker | `infra/docker/*.Dockerfile`, `infra/docker-compose.prod.yml` |
| Reverse proxy + HTTPS + HSTS | `infra/nginx/hayattek.conf` |
| تخزين ملفات خاص | S3 متوافق (أي مزود) — حاوية خاصة |
| النسخ الاحتياطي والاستعادة | `infra/backup/backup.sh`, `restore.sh`, `manage.py check_restore` |
| المراقبة والسجلات | سجلات JSON بلا PHI، `/api/health` و`/api/health/ready`؛ أداة تتبع أخطاء (مثل Sentry مستضاف ذاتياً) قرار لاحق |
| العمليات الخلفية | worker + beat (فحص الملفات المعلقة، إرسال الرسائل، حذف التسجيلات المنتهية) |

**تنبيه:** لا يُفترض أن أي خادم حالي (Hetzner أو غيره) مناسب تلقائياً لبيانات صحية: يلزم تقييم موقع البيانات قانونياً، والعزل (خادم مخصص للمنصة فقط)، والتشفير على مستوى القرص، والنسخ خارج الموقع، وصلاحيات الوصول الإداري.
