## ما تم تنفيذه واختباره فعلياً

### Backend (`backend/`)
- 13 وحدة Django: core، accounts، organizations، practitioners، patients، access، clinical، medications، diagnostics، documents، referrals، notifications، audit.
- محرك صلاحيات مركزي `apps/access/policy.py` (سجلات المنشأة + سجلات الشبكة بموافقة، فحص لكل سجل، 404 للمرفوض مع تدقيق).
- موافقات بثلاث طرق (تطبيق المريض، OTP، حضوري موثق)، وإلغاء من المريض، ونطاقات ومدد.
- دورة حياة السجلات: مسودة ← معتمد ← تصحيح موثق بنسخ (`RecordVersion`) ← إلغاء.
- سجل تدقيق محمي بـTrigger في PostgreSQL.
- الوصفات المنظمة + توليد التعليمات العربية + طباعة + تحقق عام لا يكشف الأدوية.
- طلبات التحليل والتصوير، وصندوق وارد المختبر، وتقارير منظمة، ومنحنى نتيجة عبر الزمن مفصول حسب الوحدة.
- رفع ملفات بفحص التوقيع الحقيقي (magic bytes) وحجم وSHA-256، وتنزيل عبر فحص الصلاحية.
- طلبات انضمام المنشآت (عامة + قائمة للإدارة).
- تفعيل حساب المريض من الاستقبال برابط لمرة واحدة (SMS/بريد) — الموظف لا يرى كلمة المرور.
- **الاختبارات: 43 اختباراً ناجحاً** (`uv run pytest`)، منها:
  - `test_full_acceptance_scenario` — **سيناريو القبول بخطواته العشرين كاملاً عبر الـAPI وقاعدة البيانات الحقيقية**.
  - 15 اختبار عزل وأمان (IDOR، تزوير سياق المنشأة، الاستقبال، مدير المنشأة، مدير المنصة، انتهاء الموافقة، الإلغاء، عدم تعديل سجل طبيب آخر، الطبيب غير المعتمد، المنشأة المعلقة، الطبيب متعدد المنشآت، حماية التدقيق على مستوى قاعدة البيانات).
  - المصادقة: القفل بعد 5 محاولات، عدم كشف وجود الحساب، الدخول بالهاتف السوري، توكن الموبايل (hash فقط + إبطال)، MFA.
- `ruff check` نظيف. `manage.py check --deploy` بإعدادات الإنتاج: لا تحذيرات أمنية.

### الويب (`apps/web/`)
- نظام تصميم عربي RTL، وضع ليلي، خط IBM Plex Sans Arabic.
- عام: الصفحة الرئيسية، للأطباء (مع نموذج انضمام يعمل)، الخصوصية، الشروط (مسودات)، التحقق من وصفة، صفحة مسح البطاقة العامة.
- الطبيب والاستقبال: الرئيسية، البحث (Ctrl+K)، تسجيل مريض مع كشف المكررات، ملف المريض (ملخص + سجل زمني + إجراءات)، محرر الزيارة (حفظ تلقائي، علامات حيوية، تشخيصات، اعتماد، تصحيح موثق، نسخ)، محرر الوصفة (مفضلة، قوالب، حقول منظمة، معاينة حية للتعليمات)، طباعة A4، طباعة البطاقة، المسح بالكاميرا أو بالرقم، طلبات الموافقة، الطلبات المخبرية والتصويرية، رفع المستندات، الإحالات، أدويتي وقوالبي.
- المريض: الرئيسية، البطاقة، الملف الطبي، الوصفات، التحاليل مع منحنى، المستندات، المشاركة والموافقات وسجل الوصول، العائلة، الإعدادات، الإشعارات، الأمان (كلمة المرور وMFA).
- الإدارة والمنشأة والمختبر: انظر قسم "قيد التنفيذ".
- **اختبار E2E (Playwright) ناجح:** الاستقبال يسجل مريضاً ← الطبيب يبحث ← زيارة ← اعتماد ← وصفة من المفضلة ← اعتماد وطباعة ← تظهر في السجل الزمني (`pnpm test:e2e`).
- `tsc --noEmit` نظيف.

## غير مكتمل (بصراحة)
| البند | الحالة |
|---|---|
| OCR | واجهة مزود + مهمة Celery + نموذج نتائج فقط. **لا يوجد محرك OCR ولا شاشة مراجعة**. اختيار المحرك (محلي/خارجي) قرار يحتاج موافقة لأن خدمات خارجية ستعالج بيانات مرضى. |
| الرسائل النصية (OTP) | واجهة `SmsProvider`؛ في التطوير تُطبع في السجل. **اختيار مزود حقيقي قرار تكلفة للمالك.** |
| البريد | Console في التطوير؛ يحتاج إعداد SMTP. |
| فحص الفيروسات | واجهة `MalwareScanner` (Noop). ClamAV مطلوب في الإنتاج. |
| DICOM / PACS | الملفات تُخزن فقط؛ لا عارض. مرحلة لاحقة (Orthanc + OHIF). |
| PDF من الخادم | الطباعة من المتصفح (ADR-009). أرشفة PDF ثابت لاحقاً. |
| دمج ملفات المرضى المكررة | الكشف موجود؛ **إجراء الدمج مع المراجعة البشرية غير منفذ**. |
| حسابات الأوصياء | ✅ الاستقبال يربط وصياً بملف القاصر (حتى سن 18 تلقائياً)، والوصي يتابع من حسابه. ينقص: إلغاء الوصاية من الواجهة. |
| إجراء الطوارئ Break-glass | مؤجل عمداً حتى مراجعة قانونية. |
| فرض MFA | مفعّل في إعدادات الإنتاج (`HAYAT_ENFORCE_MFA`)؛ الواجهة تعرض تنبيهاً، والفرض على مستوى كل endpoint يحتاج إكمالاً. |
| الإنجليزية | البنية جاهزة (`lib/i18n/en.ts`)، والترجمة جزئية. |
| النسخ الاحتياطي واختبار الاستعادة | لم يُنفذ (المرحلة 6). |

## المشكلات المعروفة
- `localhost` على Windows بطيء للاتصال بقاعدة البيانات (IPv6) — استخدم `127.0.0.1` (موثّق في README).
- صور MinIO لم تعد متاحة؛ استُبدلت بـSeaweedFS (ADR-016).
