# خطة الاختبار اليدوي لتطبيق الموبايل (Android و iPhone)

> **لماذا هذه الوثيقة؟** لا يوجد على جهاز التطوير محاكي Android ولا ADB ولا هاتف متصل، ولا جهاز Mac لمحاكي iOS. لذلك **لم يُختبر التطبيق على هاتف حقيقي**. ما اختُبر آلياً موثق في القسم الأخير. كل ما يتعلق بالكاميرا الحقيقية، والميكروفون الحقيقي، وأذونات النظام، وسلوك الشبكة الفعلي، والتخزين الآمن (Keychain/Keystore) يحتاج التنفيذ اليدوي أدناه.
>
> البيانات المستخدمة **اصطناعية فقط** (حسابات `@hayattek.test`). لا تستخدم بيانات مرضى حقيقيين، ولا تسجّل أصوات أشخاص حقيقيين مع المزود التجريبي.

## 1. المتطلبات

| العنصر | التفاصيل |
|---|---|
| حاسوب التطوير (Windows) | Node 22+، pnpm 11، Python/uv للخادم (كما في `README.md`) |
| حساب Expo | مجاني، لبناء نسخة التطوير عبر EAS: `npx eas-cli@latest login` |
| هاتف Android | Android 10 أو أحدث، مع تفعيل «التثبيت من مصادر غير معروفة» |
| iPhone | iOS 16 أو أحدث. البناء لـ iPhone حقيقي يحتاج **حساب Apple Developer** (مدفوع) لتسجيل الجهاز؛ إن لم يتوفر فاختبر Android فقط ووثّق ذلك |
| الشبكة | الهاتف والحاسوب على **نفس شبكة Wi-Fi** |

## 2. تشغيل الخادم بحيث يصل إليه الهاتف

1. اعرف عنوان IP للحاسوب على الشبكة المحلية:
   ```powershell
   ipconfig
   ```
   خذ قيمة `IPv4 Address` لمحول الـ Wi-Fi، مثلاً `192.168.1.20`.
2. شغّل Django على كل الواجهات (وليس 127.0.0.1 فقط):
   ```powershell
   cd D:\hayattek\backend
   uv run python manage.py runserver 0.0.0.0:8100
   ```
   إعدادات التطوير (`config/settings/dev.py`) تسمح بأي `ALLOWED_HOSTS`. لا تشغّل هذا الإعداد على شبكة عامة أو خادم إنتاج.
3. **الجدار الناري في Windows:** عند أول تشغيل اختر «السماح» للشبكات الخاصة، أو أضف القاعدة يدوياً (PowerShell كمسؤول):
   ```powershell
   New-NetFirewallRule -DisplayName "HayatTek dev API 8100" -Direction Inbound -Protocol TCP -LocalPort 8100 -Action Allow -Profile Private
   New-NetFirewallRule -DisplayName "Expo Metro 8081" -Direction Inbound -Protocol TCP -LocalPort 8081 -Action Allow -Profile Private
   ```
   تأكد أن الشبكة مصنفة «خاصة» (Private) في إعدادات Windows، وليست «عامة».
4. تحقق من الهاتف: افتح متصفح الهاتف على `http://192.168.1.20:8100/api/docs/` (واجهة توثيق الـAPI). إن لم يفتح فالمشكلة في الشبكة/الجدار الناري وليست في التطبيق.
5. إن لم تكن البيانات التجريبية موجودة: `uv run python manage.py seed_demo`.
6. HayatTek AI يجب أن يكون مفعلاً للطبيب التجريبي من Super Admin (صفحة المحافظ في الويب، أو `POST /api/v1/billing/admin/practitioners/{id}/ai-access` بـ `{"enabled": true}`).

## 3. بناء وتثبيت نسخة التطوير (Development Build)

التطبيق يستخدم وحدات أصلية غير موجودة في Expo Go بالضرورة (`expo-audio` AudioStream، `expo-network`، `expo-secure-store`، `expo-camera`)، لذا **استخدم نسخة تطوير** وليس Expo Go.

```powershell
cd D:\hayattek\apps\mobile
npx eas-cli@latest login
npx eas-cli@latest build:configure          # مرة واحدة: ينشئ eas.json
# Android: ملف APK للتثبيت المباشر
npx eas-cli@latest build --profile development --platform android
# iPhone: سجّل الجهاز أولاً ثم ابنِ
npx eas-cli@latest device:create
npx eas-cli@latest build --profile development --platform ios
```

- Android: افتح رابط البناء من الهاتف، نزّل ملف `.apk` وثبّته.
- iPhone: افتح رابط البناء من Safari وثبّت، ثم فعّل «وضع المطوّر» من الإعدادات > الخصوصية والأمان.

ثم شغّل خادم Metro مع توجيه التطبيق إلى عنوان الحاسوب:

```powershell
cd D:\hayattek\apps\mobile
$env:EXPO_PUBLIC_API_URL = "http://192.168.1.20:8100"
npx expo start --dev-client --lan
```

افتح التطبيق المثبت على الهاتف، واختر الخادم الظاهر (أو امسح رمز QR الذي يظهر في الطرفية).

> ملاحظات:
> - `EXPO_PUBLIC_API_URL` تُقرأ عند تجميع الحزمة؛ إن غيّرتها أعد تشغيل `expo start` مع `--clear`.
> - بدون هذا المتغير يتصل Android بـ `10.0.2.2:8100` (عنوان المضيف في **المحاكي** فقط) فيفشل الاتصال على هاتف حقيقي.
> - نسخة التطوير على Android تسمح بـ HTTP غير المشفر. نسخة إنتاج (release) تتطلب HTTPS.
> - إن فشلت الطلبات على iPhone فقط فالسبب غالباً App Transport Security مع HTTP؛ سجّل ذلك في النتائج.

## 5. حالات الاختبار

نفّذ كل حالة على **Android** و **iPhone**، وسجّل النتيجة في جدول النتائج (القسم 6) بالرمز نفسه.

### A. التشغيل وتسجيل الدخول والاتصال

| الرمز | الخطوات | النتيجة المتوقعة |
|---|---|---|
| A1 | افتح التطبيق لأول مرة | شاشة الدخول بالعربية، الاتجاه من اليمين لليسار، الخط عربي واضح، لا شاشة بيضاء أو خطأ أحمر |
| A2 | أدخل حساب المريض بكلمة مرور خاطئة | رسالة خطأ عربية واضحة، لا يحدث دخول |
| A3 | أدخل حساب المريض الصحيح | تظهر الرئيسية مع اسم «مريض تجريبي» والرقم الصحي |
| A4 | أغلق التطبيق كلياً من قائمة التطبيقات ثم افتحه | يبقى مسجلاً (الرمز في Keychain/Keystore) وتُحمّل البيانات من جديد |
| A5 | أوقف خادم Django ثم اسحب للتحديث في الرئيسية | رسالة «تعذّر الاتصال بالخادم…» مع زر إعادة المحاولة، لا انهيار |
| A6 | أعد تشغيل الخادم واضغط «إعادة المحاولة» | تعود البيانات |
| A7 | المزيد ← تسجيل الخروج ← تأكيد | العودة لشاشة الدخول؛ إعادة فتح التطبيق تطلب الدخول مجدداً |

### B. ملف المريض والوصفات والتحاليل و QR

| الرمز | الخطوات | النتيجة المتوقعة |
|---|---|---|
| B1 | الرئيسية ← أحدث السجلات | قائمة السجلات مع تواريخ عربية وأرقام لاتينية وشارات الحالة |
| B2 | تبويب «السجل» ← مرر للأسفل | تحميل صفحات إضافية، «لا يوجد المزيد» في النهاية |
| B3 | افتح وصفة | أسماء الأدوية والجرعات مقروءة (مثل `500 mg` لا تنقلب)، تعليمات الجرعة بالعربية |
| B4 | المزيد ← التحاليل ← افتح تقريراً | القيم مع الوحدات والمجال المرجعي، القيم غير الطبيعية مميزة |
| B5 | المزيد ← المستندات ← افتح مستنداً | يفتح المستند أو يعرض خيار المشاركة/الفتح بتطبيق آخر |
| B6 | تبويب «بطاقتي» | رمز QR واضح والرقم الصحي، السطوع مناسب للمسح |
| B7 | امسح رمز QR من هاتف آخر بتطبيق الكاميرا العادي | يظهر رابط بطاقة HayatTek (لا بيانات طبية داخل الرمز) |

### C. الكاميرا ومسح البطاقة (وضع الطبيب)

| الرمز | الخطوات | النتيجة المتوقعة |
|---|---|---|
| C1 | ادخل بحساب الطبيب ← المزيد ← وضع الطبيب ← «مسح البطاقة» (أول مرة) | يظهر طلب إذن الكاميرا من النظام بالنص العربي «يحتاج تطبيق حياة إلى الكاميرا لمسح رمز البطاقة الصحية.» |
| C2 | ارفض الإذن | رسالة عربية مع زر «السماح باستخدام الكاميرا»، والإدخال اليدوي متاح، لا انهيار |
| C3 | امنح الإذن من الإعدادات وعد | تعمل الكاميرا الخلفية مع إطار المسح |
| C4 | امسح بطاقة المريض المعروضة على هاتف آخر (B6) | يُفتح ملف «مريض تجريبي» مباشرة |
| C5 | امسح رمز QR لا علاقة له (مثلاً رابط موقع) | رسالة «هذا الرمز ليس بطاقة صحية…» |
| C6 | أدخل الرقم الصحي يدوياً `2314504354` | يُفتح الملف نفسه |

### D. الميكروفون و HayatTek AI (وضع الطبيب)

| الرمز | الخطوات | النتيجة المتوقعة |
|---|---|---|
| D1 | ملف المريض ← «زيارة جديدة» | تظهر بطاقة HayatTek AI (فقط إن كانت الخدمة مفعلة من الإدارة) |
| D2 | من الإدارة أوقف الخدمة للطبيب ثم أعد فتح الزيارة | لا يظهر زر التسجيل؛ تظهر عبارة «الخدمة غير مفعلة لحسابك…» والكتابة اليدوية تعمل. أعد التفعيل بعدها |
| D3 | «HayatTek AI — تسجيل الزيارة» ← «بدء الاستماع الذكي» دون اختيار موافقة | رسالة «سجّل موافقة المريض…» ولا يبدأ التسجيل |
| D4 | اختر «وافق شفهياً» ← «بدء الاستماع الذكي» (أول مرة) | طلب إذن الميكروفون من النظام بالنص العربي (iOS) / طلب RECORD_AUDIO (Android) |
| D5 | ارفض الإذن | بطاقة «إذن الميكروفون» مع شرح عربي وزر «فتح الإعدادات» و«الكتابة يدوياً»؛ لا انهيار |
| D6 | امنح الإذن من الإعدادات ← ارجع ← ابدأ | نقطة حمراء نابضة «جارٍ التسجيل» وعداد يتقدم ومؤشر مستوى الصوت يتحرك عند الكلام. **iOS:** يظهر مؤشر الميكروفون البرتقالي في الشريط العلوي. **Android 12+:** يظهر مؤشر الميكروفون الأخضر |
| D7 | «إيقاف مؤقت» ثم انتظر 5 ثوانٍ ثم «استئناف» | العداد يتوقف أثناء الإيقاف ويستأنف |
| D8 | أثناء التسجيل اضغط زر الشاشة الرئيسية ثم عد للتطبيق | التسجيل **متوقف مؤقتاً** مع رسالة «أُوقف التسجيل مؤقتاً لأن التطبيق انتقل إلى الخلفية»؛ لا تسجيل في الخلفية |
| D9 | سجّل إملاءً اصطناعياً بصوتك لمدة 10–20 ثانية (لا تذكر بيانات حقيقية) ← «إنهاء وتحليل» | شريط رفع بنسبة مئوية، ثم «جارٍ التحليل…» ثم «المسودة جاهزة للمراجعة». مع المزود التجريبي يكون النص تجريبياً عاماً وتظهر لافتة «مزود تجريبي» |
| D10 | (التحقق من صيغة الصوت) بعد D9 افتح في الويب `/app/encounters/<id>/scribe/<session>` أو اطلب `GET /api/v1/scribe/sessions/<id>` | `audio_seconds` قريبة من مدة التسجيل الفعلية (دون فترات الإيقاف). **هذا يثبت أن الهاتف أنتج WAV PCM مقبولاً** — إن ظهر خطأ «صيغة التسجيل غير مدعومة» سجّله فوراً |
| D11 | أعد D9 لكن فعّل وضع الطيران مباشرة بعد «إنهاء وتحليل» | «لم يكتمل رفع التسجيل» + لافتة عدم الاتصال، وزر «إعادة رفع التسجيل» معطل |
| D12 | أطفئ وضع الطيران ← «إعادة رفع التسجيل» | يكتمل الرفع؛ في الويب/API تظهر **جلسة واحدة فقط** لهذه الزيارة (لا تكرار) |
| D13 | تسجيل اختبار اصطناعي: اختر «حوار: ألم صدري» ← «استخدام» | تصبح المسودة جاهزة خلال ثوانٍ |
| D14 | «مراجعة المسودة الذكية» | النص مع شارات «الطبيب/المريض»، العلامات الحيوية (150/90، نبض 86)، تشخيص «مشتبه» مميز بالأصفر، الدواء غير المسمى غير محدد افتراضياً، «المصدر: «…»» تحت كل عنصر |
| D15 | ألغِ تحديد أحد التحاليل، اكتب تقييماً، ← «تطبيق على الزيارة» ← تأكيد | العودة لشاشة الزيارة مع «طُبّقت مسودة HayatTek AI…» و«أُنشئت وصفة كمسودة»، وحقل التقييم يعرض ما كتبته |
| D16 | «فتح الوصفة (مسودة)» | الوصفة بحالة «مسودة» وليست معتمدة |
| D17 | سجّل لمدة أقل من ثانية ← إنهاء | رسالة «التسجيل قصير جداً» ولا يُرفع شيء |

### E. حسابي المالي (الطبيب)

| الرمز | الخطوات | النتيجة المتوقعة |
|---|---|---|
| E1 | وضع الطبيب ← «حسابي المالي» (أو المزيد ← حسابي المالي) | الرصيد الحالي، إن كان سالباً فهو **أحمر** مع «مدين للمنصة» و«المبلغ المستحق» بالقيمة الموجبة |
| E2 | قارن الأرقام بصفحة `/app/wallet` في الويب | الرصيد، الإجمالي، الدقائق، سعر الدقيقة، المدفوعات متطابقة |
| E3 | مرر كشف الحساب | كل عملية: النوع، التاريخ، المبلغ (+ أخضر للدفعات، − أحمر للرسوم)، الرصيد بعدها، رقم الإيصال للدفعات |
| E4 | ابحث عن أي حقل تعديل أو تكلفة داخلية/هامش | **لا يوجد** — الصفحة للاطلاع فقط |
| E5 | سجّل دفعة للطبيب من الويب كمدير ثم اسحب للتحديث على الهاتف | تظهر الدفعة ويتغير الرصيد |

| الرمز | الخطوات | النتيجة المتوقعة |

| F6 | أغلق التطبيق دون اتصال ثم افتحه | لا تظهر أي بيانات طبية سابقة (لا تخزين للبيانات الطبية على الجهاز) |

## 8. ملاحظات تقنية حول التسجيل الصوتي

- الخادم يقبل **WAV PCM فقط** ويحسب المدة (أساس الفوترة) من ترويسة WAV.
- `useAudioRecorder` في expo-audio لا يدعم WAV على Android (الصيغ المتاحة: 3gp/mpeg4/amr/aac/webm). لذلك يستخدم التطبيق `useAudioStream` (عينات PCM خام int16، 16 kHz أحادي) ويبني ملف WAV في الذاكرة بنفسه — نفس الناتج على Android و iOS، ولا يُكتب التسجيل على تخزين الهاتف. إن سلّم العتاد معدلاً آخر (مثل 48 kHz) أو قناتين، يُدمج الصوت ويُعاد تشكيله إلى 16 kHz قبل الترميز.
- لا يُرسل أي ملف غير WAV. إن تبيّن في D10 أن جهازاً ما لا يسلّم PCM عبر AudioStream، فالبديل الموثق هو «تسجيل اختبار اصطناعي» للتجربة، والحل الدائم يكون محوّل صيغ في الخادم (غير منفذ حالياً).
- التسجيل يبقى في ذاكرة التطبيق فقط حتى يكتمل الرفع (لإعادة المحاولة)، ويُحذف من الذاكرة بعده أو عند «حذف التسجيل» أو إغلاق التطبيق.
